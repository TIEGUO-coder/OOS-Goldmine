# Contributing / 贡献指南

Thanks for helping improve OSS Goldmine.

感谢你帮助改进开源金矿。

## Good First Contributions / 适合第一次贡献

- Add better scoring signals / 增加更好的评分信号
- Improve issue clustering / 改进 issue 聚类
- Add high-quality opportunity examples / 增加高质量机会样例
- Improve README wording or screenshots / 改进 README 文案或截图
- Report false positives / 反馈误判案例

## What Makes a Good Opportunity Card / 什么是好的机会卡

A strong card should explain:

一张好的机会卡应该说明：

- Why demand is still alive / 为什么需求还活着
- Why maintenance appears to be slowing / 为什么维护看起来变慢
- What existing alternatives already solve / 现有替代品已经解决了什么
- What small wedge is still worth building / 还有哪个小切口值得做
- Why this respects the original maintainers / 为什么这尊重原维护者

## Development / 开发

```bash
npm install
npm run dev
npm run build
```

## Pull Requests / PR

Please keep changes focused. A useful pull request should include:

请保持改动聚焦。一个有用的 PR 应该包含：

- Clear before/after behavior / 清楚说明改动前后行为
- Reasoning for scoring changes / 如果改评分，说明理由
- Sample repos used for testing / 用于测试的样例 repo
- Screenshots for UI changes / UI 改动请附截图

## Tone / 表达原则

OSS Goldmine should never shame maintainers.

开源金矿不应该羞辱维护者。

Use respectful language:

使用尊重的表达：

- Good: maintenance is fading / 维护正在变慢
- Good: demand is still alive / 需求仍然活跃
- Good: companion tool / 配套工具
- Avoid: dead repo / 死仓库
- Avoid: steal this idea / 偷这个点子
